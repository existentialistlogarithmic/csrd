## REFERENCE TAXONOMY (ESRS Set 1)

Use these exact DR codes as your controlled vocabulary. Cross-cutting minimum disclosure
requirements (MDR-P/A/M/T) recur inside each topical standard — tag them with the parent standard
(e.g. `E1 / MDR-T`).

### Cross-cutting minimum disclosure requirements (apply within each material topical standard)
- `MDR-P` — Policies adopted to manage material sustainability matters
- `MDR-A` — Actions and resources in relation to material sustainability matters
- `MDR-M` — Metrics in relation to material sustainability matters
- `MDR-T` — Tracking effectiveness of policies and actions through targets

### ESRS 1 — General Requirements
Architectural standard (double materiality, value chain, time horizons, structure). Not itself a set
of numbered DRs; flag references to it as `ESRS1 / general-requirements` where relevant (e.g.
statements about materiality methodology, reporting boundary, phase-in reliefs).

## EXTRACTION METHOD (follow in order)

Think step by step internally, then emit only the JSON output.

1. **Segment.** Split the document into logical sections using headings, DR-code mentions
   (e.g. "E1-6", "Gross Scope 1"), and the ESRS index table if present (companies often include an
   IRO-2 content index mapping DRs to page numbers — treat it as a high-value map, not as evidence
   of substantive disclosure).
2. **Locate the materiality assessment.** Find the double materiality results (usually near
   IRO-1/IRO-2/SBM-3). Record which topical standards the company deemed material vs. not material.
3. **For each DR in the taxonomy**, search the segmented text for substantive content. Match on DR
   code, DR title keywords, and semantic content — not code strings alone (many reports narrate
   without citing codes).
4. **Classify status** into one of:
   `reported` · `not_material_omitted` · `material_not_reported` · `not_addressed` · `phase_in_deferred`
   (use `phase_in_deferred` where the company invokes a first-year/phase-in relief, e.g. Scope 3,
   anticipated financial effects, or value-chain data).
5. **Extract datapoints.** For quantitative DRs, pull each metric with value, unit, scope/breakdown,
   reporting period, baseline year, target year, and comparative (prior-year) value if given.
6. **Score confidence** 0.0–1.0 based on evidence strength and ambiguity.
7. **Flag greenwashing/quality signals** where relevant: vague commitments without targets, targets
   without baselines, missing Scope 3, non-GHG offsets counted toward gross reductions, boilerplate
   policy language with no actions. Keep these observational, not judgemental.

- `status` and `confidence` are required on every disclosure object.
- Emit one object per DR you evaluated; at minimum emit all ESRS 2 DRs plus every DR of each material

## FEW-SHOT ANCHORS (behaviour calibration)

**Positive — substantive disclosure:**
> Input text: "In FY2024 our gross Scope 1 emissions were 124,500 tCO2e (2023: 131,200 tCO2e),
> calculated using the operational-control approach."
> → `E1-6`, status `reported`, datapoints for Scope 1 with prior-year value, confidence high.

**Negative — index entry only (do NOT mark reported):**
> Input text: "E1-6 Gross GHG emissions ................. p.87" (a content-index row)
> → Use it to locate p.87; only classify `reported` after finding substantive text there. An index
> row alone is not evidence of disclosure.

**Materiality omission (valid, not a gap):**
> Input text: "Following our double materiality assessment, biodiversity (ESRS E4) was not assessed
> as material; accordingly no E4 disclosures are provided."
> → All E4 DRs: status `not_material_omitted`, confidence high. Do not flag as missing.

**Phase-in relief:**
> Input text: "We have applied the first-year phase-in and omitted anticipated financial effects
> (E1-9) for this reporting period."
> → `E1-9`, status `phase_in_deferred`.
